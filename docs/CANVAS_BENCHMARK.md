# Phase 2 原生画布验收

## 图模型与工作区

- P2-01 使用固定 seed `20261121` 生成 50、150、300、500 个节点，分别配有 100、300、600、1000 条关系。每个规模覆盖疏密两种布局、交叉关系、双语长名和字段。关系由五点折线表示，首尾位于对应节点的端口。
- P2-02 以 World 表示模型单位，以 Viewport 表示画布局部 DIP，以 Screen 表示窗口内容 DIP。DPI 换算由 MyGo 执行。单测覆盖非零画布偏移、双向换算、缩放限位下的光标锚定、平移和全图适应。
- P2-03 使用静态节点 BVH 和关系线段 BVH，候选边经过精确折线判定。四个规模各 71 个区域与线性扫描完全一致。在 Apple M4 宿主机针对 500 节点密集图运行 `go test -run '^$' -bench '^BenchmarkSpatialQueries$' -benchmem -benchtime=150ms ./internal/graph`，节点和边合计查询耗时从线性局部 7.90 µs 降到 1.47 µs，全图从 5.68 µs 降到 0.60 µs。
- P2-04 在三栏原生应用中默认打开 50 节点密集模拟图。用拖动或滚轮平移，使用 Ctrl + 滚轮或触控板捏合按指针位置缩放，也可以使用工具栏从中心缩放。「适应选中」将所选表或关系放入窗口，「显示全部」将整幅图放入窗口。工具栏复用应用双语资源，语言切换保留选区和相机。
- 绘制前按视口查询节点与边。边可保留跨越视口的可见部分，查询范围覆盖描边半宽。远景为表轮廓，中景为标题和两行关键字段，近景为标题和全部五行模拟字段。两个切换区间分别为 `0.36–0.44` 和 `0.75–0.85`，区间内保留原档位。长文字在排版时按卡片可用宽度添加省略号，所选表的完整名称显示在右栏。
- 50 节点原生工作区于 2026-11-21 通过 MyGo 本地 automation 运行。检查鼠标命中、拖动后旧位置失去命中、新位置命中、光标锚点、适应选中、显示全部、800×600 窗口的四个工具按钮和正常关闭。2× 近景、中景及全图截图分别为 `.out/phase2/native-near.png`、`native-medium.png` 和 `native-all.png`。原生帧日志报告 GPU 提交。

## 设备与统计口径

2026-11-21，Apple M4（Mac16,10，10 核 GPU）、16 GiB，macOS 15.8.1（24H32），Metal，显示器 5120×2880，等效 2560×1440 @ 60 Hz，2×。Go 1.27.4、MyGo v0.10.0，默认优化的 macOS arm64 构建，`CGO_ENABLED=0`。使用与当日原生工作区相同的渲染器与图查询，独立窗口的整块内容区用于承载画布。

FPS 与帧间隔 P95 按采样区间内连续 Draw 回调完成时间统计，包含刷新调度等待。MyGo 帧日志另行统计框架每帧从开始到提交的耗时，包含报告的 present 阶段。CPU 取进程的 `(user+sys)/real`，以一个核心为 100%，峰值 RSS 按 `/usr/bin/time -lp` 的字节数换算为 MiB，两者覆盖进程启动、预热、采样和退出。缓存命中率统计可复用原生网格纹理的查找，预排版文字独立保留。

窗口内容为 1200×800 DIP（2400×1600 像素）。每组预热 2 秒，采样 10 秒。基准用 `Painter.AnimationFrame()` 请求下一帧，使用 MyGo 默认刷新节奏。相机每 5 秒执行一轮适应全图、放大到 1.05×、平移、切换到 0.55× 和 0.22×、返回近景和全图。每帧按绝对经过时间求位置和缩放，采样覆盖两轮。在 `CANVAS_BENCH BEGIN` 与 `CANVAS_BENCH END` 之间读取 MyGo 帧日志。P95 使用最近秩。绘制回调次数可能略高于 GPU 提交日志的帧数，两项计数分别保留。

## 性能调整

500 节点密集图的 0.5 秒预热、2 秒采样短测中，最初的卡片内逐节点变换裁剪仅有 18.67 FPS。MyGo 日志显示慢帧主要花在 GPU 提交，变换裁剪在 MyGo v0.10.0 中需要生成遮罩。改为在构建场景时为标题和字段预排版省略号后，画布只保留外围裁剪，同样的短测达到 60.48 FPS。

## 实测结果

前三组采样时长均为 10 秒。500 节点为 2 秒诊断短测，尚未覆盖一轮完整轨迹。四组均报告原生窗口、无网页内容及 2× DPI，采样区间内的 MyGo 帧日志均为 GPU 提交。

50、150、300 节点长测中的 MyGo GPU 提交日志分别为 600、594、600 帧。500 节点短测为 121 帧。四组网格命中率均为 100%，首次纹理构建发生在预热期。原始记录在 `.out/phase2/bench-dense-{50,150,300}.log` 和 `.out/phase2/bench-smoke-labels.log`。

500 节点长测在预热时停止重绘并触发 27 秒看门狗。改用窗口级主动重绘后仍超时，Phase 0 的旧探针同样只绘制首帧。随后读取到控制台处于锁屏状态。两次超时分别保留在 `.out/phase2/bench-dense-500.log` 和 `.out/phase2/final/bench-dense-500.log`。待解锁后完成 500 节点密集图长测及四组稀疏图长测，Phase 2 性能门禁待签核。

## 复现

```sh
mkdir -p .out/phase2/final
CGO_ENABLED=0 go build -mod=readonly -o .out/phase2/final/canvas-bench ./cmd/canvas-bench
for density in dense sparse; do
  for nodes in 500 50 150 300; do
    caffeinate -di env -u MYGO_UNCAPPED MYGO_FRAME_STATS=all /usr/bin/time -lp \
      .out/phase2/final/canvas-bench -nodes "$nodes" -density "$density" \
      -seed 20261121 -warmup 2s -sample 10s \
      > ".out/phase2/final/bench-$density-$nodes.log" 2>&1 || exit 1
  done
done
```
